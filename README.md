# EarthMart POS — Phase 1

ระบบขายหน้าร้าน + สต็อก สำหรับมินิมาร์ท ใช้ Google Sheets เป็นฐานข้อมูล

```
┌─────────────────────────────┐     fetch (HTTPS)     ┌──────────────────────────┐     ┌──────────────┐
│ หน้าเว็บ  web/  (JavaScript) │ ────────────────────▶ │ Apps Script  gas/ (API)  │ ──▶ │ Google Sheet │
│ GitHub Pages / host ไหนก็ได้ │ ◀──────────────────── │ doPost → api_*           │     └──────────────┘
└──────────────┬──────────────┘        JSON           └──────────────────────────┘
               │ Web Serial / WebUSB (ESC/POS)
       เครื่องพิมพ์ใบเสร็จ ──RJ11── ลิ้นชักเก็บเงิน
```

| โฟลเดอร์ | คืออะไร |
|---|---|
| `gas/` | โค้ดฝั่งเซิร์ฟเวอร์ (Apps Script) — เป็น API อย่างเดียว ไม่มีหน้าเว็บ |
| `web/` | หน้าโปรแกรมทั้งหมด (HTML/CSS/JS ล้วน) — เอาขึ้น GitHub Pages หรือ host ไหนก็ได้ที่เป็น **https** |
| `test/` | ชุดทดสอบ (เซิร์ฟเวอร์ 70 จุด + ทดสอบหน้าจอในเบราว์เซอร์) |
| `.github/workflows/` | Deploy อัตโนมัติ: `web/` → GitHub Pages, `gas/` → Apps Script |
| `products_template.csv` | ตัวอย่างไฟล์นำเข้าสินค้า |

## 1) ตั้ง Google Sheet + Apps Script (ครั้งแรก)

1. สร้าง Google Sheet ใหม่ ตั้งชื่อเช่น `EarthMart DB`
2. เมนู **ส่วนขยาย › Apps Script**
3. วางไฟล์ทุกไฟล์ใน `gas/` (สร้างไฟล์ชื่อเดียวกัน: `Code`, `Auth`, `Products`, `Sales`, `Shifts`, `Stock`, `Reports`, `Admin`)
   - ไฟล์ `appsscript.json`: ไปที่ ⚙️ Project Settings › ติ๊ก *Show "appsscript.json"* แล้ววางทับ
   - หรือใช้ clasp (ข้อ 4) ไม่ต้องวางเอง
4. เลือกฟังก์ชัน `setup` › กด **Run** › อนุญาตสิทธิ์
   - ผลลัพธ์จะแสดง **API key** (ดูซ้ำได้ด้วยฟังก์ชัน `showApiKey`)
5. สร้างบัญชีเจ้าของ: เพิ่มฟังก์ชันชั่วคราวแล้วรัน
   ```js
   function firstOwner() { createOwner('ชื่อเจ้าของ', '1234'); }
   ```
   (รันเสร็จลบฟังก์ชันนี้ทิ้งได้ — PIN เก็บแบบเข้ารหัส)
6. Backup อัตโนมัติทุกวันตี 2: รันฟังก์ชัน `installTriggers` หนึ่งครั้ง

## 2) Deploy เป็น API

1. **Deploy › New deployment** › ประเภท **Web app**
2. Execute as: **Me** · Who has access: **Anyone**
3. คัดลอก **Web app URL** (ลงท้าย `/exec`) และ **Deployment ID** เก็บไว้

> **ทำไมต้อง Anyone:** หน้าเว็บอยู่คนละโดเมนกับ Google จึงส่งการล็อกอิน Google ไปด้วยไม่ได้
> ความปลอดภัยมาจาก 3 ชั้นแทน: **API key** (ไม่มี = เรียกอะไรไม่ได้เลย) → **PIN** (ผิด 5 ครั้งล็อก 5 นาที) → **สิทธิ์ตามบทบาท/เครื่อง**
> ถ้า API key หลุด รัน `rotateApiKey` แล้วตั้งเครื่องใหม่

**แก้โค้ดภายหลัง:** Deploy › Manage deployments › ✏️ › Version: *New version* (URL เดิมไม่เปลี่ยน) — หรือให้ GitHub Actions ทำให้ (ข้อ 4)

## 3) เอาหน้าเว็บขึ้น GitHub Pages

1. สร้าง repo บน GitHub แล้ว push โฟลเดอร์นี้ทั้งหมดขึ้นไป (branch `main`)
2. repo **Settings › Pages › Source = GitHub Actions**
3. workflow *Deploy web to GitHub Pages* จะรันเอง → ได้ลิงก์ `https://<ชื่อ>.github.io/<repo>/`

host อื่นก็ได้ (Netlify, Cloudflare Pages, Firebase Hosting…) แค่อัปโหลดโฟลเดอร์ `web/` — **ต้องเป็น https** ไม่งั้นต่อลิ้นชักไม่ได้

> repo เป็น public ได้ — ไม่มี URL หรือ key อยู่ในโค้ด แต่ละเครื่องกรอกเองครั้งเดียว
> (ถ้า repo เป็น private จะใส่ค่าไว้ล่วงหน้าใน `web/config.js` ก็ได้)

## 4) Deploy Apps Script อัตโนมัติจาก GitHub (clasp)

ทำครั้งเดียวบน PC:

1. เปิด Apps Script API: <https://script.google.com/home/usersettings> › **On**
2. ติดตั้ง Node.js แล้วรัน `npx @google/clasp@2.4.2 login` → จะได้ไฟล์ `~/.clasprc.json`
3. ใน repo GitHub › Settings › Secrets and variables › Actions เพิ่ม 3 ค่า:

| Secret | เอามาจาก |
|---|---|
| `CLASPRC_JSON` | เนื้อหาไฟล์ `~/.clasprc.json` ทั้งไฟล์ |
| `GAS_SCRIPT_ID` | Apps Script › ⚙️ Project Settings › Script ID |
| `GAS_DEPLOYMENT_ID` | Deployment ID จากข้อ 2 |

หลังจากนี้แก้ไฟล์ใน `gas/` แล้ว push → GitHub รันเทสก่อน ผ่านแล้วค่อย push ขึ้น Apps Script และอัปเดต deployment เดิมให้เอง

## 5) ตั้งเครื่องหน้าร้าน

1. เปิดลิงก์หน้าเว็บด้วย **Chrome หรือ Edge** บน PC
2. ครั้งแรกจะถามการเชื่อมต่อ: ใส่ **Web app URL** + **API key** › ทดสอบและบันทึก
3. ล็อกอินเจ้าของ › **ตั้งค่า › ลงทะเบียนเป็นเครื่องหน้าร้าน** (เฉพาะเครื่องนี้ที่เปิดกะ/ขาย/ยกเลิกบิลได้)
4. ตั้งพร้อมเพย์, ชื่อร้าน, ท้ายใบเสร็จ ในหน้าตั้งค่า
5. เครื่องอื่น (มือถือเจ้าของ ฯลฯ): หน้าตั้งค่า › **คัดลอกลิงก์ตั้งค่าเครื่องอื่น** แล้วเปิดลิงก์นั้นบนเครื่องใหม่ — ไม่ต้องพิมพ์ key เอง

## 6) ลิ้นชักเก็บเงิน

ลิ้นชักเสียบที่เครื่องพิมพ์ใบเสร็จ (สาย RJ11) — หน้าเว็บส่งคำสั่ง ESC/POS `ESC p` ให้เครื่องพิมพ์เตะลิ้นชัก
ตั้งใน **ตั้งค่า › ลิ้นชักเก็บเงิน (เครื่องนี้)** แล้วกด **ทดสอบเปิด**

| โหมด | ใช้เมื่อ |
|---|---|
| **เลือกพอร์ต COM** (Web Serial) | เครื่องพิมพ์ต่อ RS-232 หรือมีไดรเวอร์ USB แบบ *Virtual COM* — เลือกง่ายสุด แนะนำ |
| **เลือก USB** (WebUSB) | เครื่องพิมพ์ USB ที่ไม่มีไดรเวอร์จับอยู่ — บน Windows ต้องเปลี่ยนไดรเวอร์เป็น WinUSB ด้วยโปรแกรม Zadig (แล้วจะพิมพ์ผ่านไดรเวอร์ Windows ไม่ได้) |
| **ปิด** | ให้ไดรเวอร์เครื่องพิมพ์เปิดลิ้นชักเองตอนพิมพ์ใบเสร็จ (ตั้งใน Printing Preferences ของไดรเวอร์ เช่น *Cash drawer: Open before printing*) |

- ถ้ากดทดสอบแล้วไม่เปิด ลองเปลี่ยน **Pin 2 ↔ Pin 5** และ Baud (ส่วนใหญ่ 9600 หรือ 115200)
- ลิ้นชักเปิดเองเมื่อ: ขายเงินสดสำเร็จ, เปิดกะ — ปุ่ม **เปิดลิ้นชัก** บนหน้าขายจะบันทึกเป็น "รายการผิดปกติ" ในรายงานทุกครั้ง

### พิมพ์ใบเสร็จไม่ให้มีหน้าต่างถาม
สร้าง shortcut ของ Chrome เพิ่ม `--kiosk-printing` ต่อท้าย Target แล้วตั้งเครื่องพิมพ์ใบเสร็จเป็น default ของ Windows · กระดาษ 80 มม.

## 6.1) จอลูกค้า (จอที่ 2)

- ต่อจอที่ 2 เข้ากับคอมเครื่องหน้าร้าน แล้วกดปุ่ม **จอลูกค้า** ที่แถบบนของหน้าขาย → ลากหน้าต่างไปจอที่ 2 → ดับเบิลคลิกให้เต็มจอ
- หรือทำ shortcut เปิดอัตโนมัติ: `chrome.exe --app="https://<เว็บของร้าน>/?page=customer" --window-position=1920,0 --kiosk`
- จอลูกค้าไม่ต้องล็อกอิน แสดงอย่างเดียว ไม่มี Dark mode (QR ต้องพื้นขาว) และได้ข้อมูลจากหน้าขายในเครื่องเดียวกันทันที ไม่ผ่านอินเทอร์เน็ต
- 4 สถานะ: ว่าง → รายการที่สแกน → ชำระเงิน (QR พร้อมเพย์ตามยอด) → เสร็จ (เงินทอน 5 วินาที) · พัก/ล้างบิล = กลับหน้าว่างทันที
- ข้อความต้อนรับ เวลาเปิด–ปิด และโปรโมชั่น ตั้งในหน้า **ตั้งค่า › ร้าน › จอลูกค้า**
- จุดสีเขียวบนปุ่ม "จอลูกค้า" = จอลูกค้าเปิดอยู่และเชื่อมต่อแล้ว

## 7) นำเข้าสินค้า

หน้า **สินค้า › นำเข้า CSV** (ใช้ `products_template.csv` เป็นแบบ)
- สินค้าเดียวมีหลายบาร์โค้ด (ชิ้น/แพ็ค/ลัง) = หลายแถว SKU เดียวกัน, `multiplier` = กี่ชิ้น, `barcodePrice` = ราคาขายหน่วยนั้น (ว่าง = ราคาชิ้น × จำนวน)
- สต็อกนับเป็นชิ้นเสมอ · `openingStock` ใช้เฉพาะตอนสร้างสินค้าใหม่
- สินค้าไม่มีบาร์โค้ด: `type=nobarcode`, ใส่ `plu` (พิมพ์รหัสสั้นที่ช่องสแกน) และ/หรือ `quickKey=y` ให้ขึ้นปุ่มขายด่วน · `openPrice=y` = ใส่ราคาตอนขาย

## 7.1) ทุนสินค้า (FIFO) และการรับสินค้า

- ทุนไม่ได้กรอกในหน้าสินค้า แต่มาจาก **หน้ารับสินค้า** — รับแต่ละครั้ง = 1 ล็อต เก็บทุนต่อชิ้นของรอบนั้น
- ขายออกจากล็อตเก่าสุดก่อน (เข้าก่อนออกก่อน) บิลเก็บทุนจริงของล็อตที่ตัด · ยกเลิกบิลคืนของเข้าล็อตเดิม
- สแกนบาร์โค้ดที่แพ็ค/ลังในหน้ารับสินค้า ระบบเลือกหน่วยและคิดทุนต่อชิ้นให้ (ใส่ทุนต่อหน่วย หรือยอดรวมของบรรทัดก็ได้)
- ดูล็อตที่เหลือ: หน้าสินค้า › เลือกสินค้า › ปุ่ม "ล็อต"
- ถ้าขายเกินสต็อก ส่วนที่ขาดคิดทุนตามทุนล่าสุด และรอบรับถัดไปจะหักส่วนนั้นออกจากล็อตใหม่ให้เอง
- สต็อกที่มีอยู่ก่อนเปลี่ยนมาใช้ FIFO จะถูกยกเป็นล็อตแรก (OPENING) ด้วยทุนเดิมโดยอัตโนมัติ
- คอลัมน์ `cost` ในไฟล์นำเข้าใช้เป็นทุนของ `openingStock` สำหรับสินค้าใหม่เท่านั้น

## 7.2) สินค้าหมดอายุ (หน้า "หมดอายุ")
- ติ๊ก **ติดตามวันหมดอายุ** ในหน้าสินค้า → ตอนรับสินค้าต้องใส่วันหมดอายุทุกครั้ง (ล็อตละวัน)
- เตือนตาม **วันที่** ไม่ขึ้นกับจำนวนคงเหลือ: ตั้งจำนวนวันเตือนล่วงหน้าแยกตามหมวดได้ (เจ้าของเท่านั้น)
- แต่ละล็อตเลือกได้ 3 แบบ (นับของล็อตนั้นบนชั้นจริงก่อน):
  - **ลดราคา** — เปิดโควตาราคาลด (เช่น −30% × 4 ชิ้น) แคชเชียร์สแกนตามปกติแล้วแตะป้าย "ใช้ราคาลด" ที่แถวสินค้า ไม่ต้องใช้ PIN · ใช้กับหน่วยชิ้นเท่านั้น · ยกเลิกบิลแล้วโควตาคืน
  - **ตัดเสีย** — ตัดสต็อกจากล็อตนั้นโดยตรง (แคชเชียร์ต้องให้เจ้าของอนุมัติ)
- เช็กสต็อกแล้วเจอของหมดอายุ ตัดที่หน้าสต็อกได้เลย (เหตุผล "หมดอายุ") — ขึ้นในแท็บ "ประวัติตัดหมดอายุ" และยอด "ตัดของหมดอายุเดือนนี้" ของหน้าหมดอายุด้วย และล็อตที่เลยวันหมดอายุจะถูกปิดจากรายการต้องจัดการ
  - **ไม่เหลือแล้ว** — ขายหมดแล้ว ปิดการเตือน ไม่ปรับสต็อก
- หน้าสต็อกมีป้ายลิงก์ไปหน้าหมดอายุ

## 7.3) เบิกใช้ในร้าน (ปุ่ม "เบิกใช้" ในหน้าขาย)
- หยิบสินค้าในร้านไปใช้เอง (น้ำให้พนักงาน ถุงขยะ ทิชชู่ ทดสอบเครื่อง) — สแกน/ค้นหาจากรายการสินค้าที่โหลดไว้แล้ว ไม่ต้องรอโหลดหน้าสต็อก
- ต้องใส่ว่าใช้ทำอะไร · แคชเชียร์ต้องให้เจ้าของอนุมัติ · สินค้าสูตรผสมจะตัดที่ส่วนประกอบ
- นับเป็นค่าใช้จ่าย แยกยอดจากของเสีย (ดูได้ที่ตัวเลขด้านบนของหน้าสต็อก) — ถ้าหยิบไปแล้วไม่บันทึก ตอนตรวจนับจะกลายเป็นสูญหาย

## 7.4) แบ่งจ่าย และคืนสินค้าบางรายการ
- **แบ่งจ่าย**: หน้าชำระเงิน › "แบ่งจ่าย" ส่วนที่ 1 เลือกได้ 3 ช่องทาง (เงินสด / QR / โอน) แล้วใส่ยอดที่รับมา · ส่วนที่ 2 เลือกจาก 2 ช่องทางที่เหลือ ยอดคิดให้ = ยอดรวม − ส่วนที่ 1 (แก้ได้ ถ้าเป็นเงินสดใส่เกินได้ ระบบทอนให้) · QR ส่วนนั้นขึ้นที่จอลูกค้า · ปิดกะนับแยกแต่ละช่องทาง
- หน้าชำระเงินมีปุ่มตัวเลขสำหรับจอสัมผัส (กดช่องยอดที่จะใส่ก่อน แล้วกดตัวเลข)
- **คืนสินค้า**: หน้าบิล › เลือกบิล › "คืนสินค้า" กด + จำนวนที่คืนต่อรายการ เลือกคืนเป็นเงินสด (ออกจากลิ้นชักของกะที่เปิดอยู่) หรือโอนคืน
  - เงินคืนหักส่วนลดท้ายบิลตามสัดส่วน · คืนครบทั้งบิลแล้วยอดคืนรวมเท่ากับยอดบิลพอดี
  - ของที่คืนกลับเข้าสต็อกทั้งหมดเป็นล็อตใหม่ราคาทุนเดิม (ลูกค้าไม่ต้องรอ) · ชิ้นที่เสียไปตัดที่หน้าสต็อก › ตัดของเสีย ทีหลัง (ตัดของเสียมีที่เดียว) · เครื่องดื่มชง/สูตรผสม คืนเงินได้แต่**ไม่รับเข้าสต็อก** (แถวสีส้มในหน้าต่างคืนสินค้า)
- **ค้นหาบิล**: หน้าบิล › ช่อง "ค้นหาเลขบิล" พิมพ์บางส่วนได้ เช่น 123 · เจอบิลเดียวเปิดให้เลย
  - แคชเชียร์ต้องให้เจ้าของอนุมัติ · บิลที่คืนบางส่วนแล้วยกเลิกทั้งบิลไม่ได้ · รายงานรายวันหักยอดคืนแล้ว

## 7.5) รายงาน (เจ้าของ)
- ปุ่ม **รายวัน / รายเดือน** คุมทั้งหน้า · รายวัน: วันนี้ / เมื่อวาน / 7 วัน / 30 วัน / เลือกวันที่ · รายเดือน: เดือนนี้ / เดือนก่อน / 3 / 6 เดือน / ปีนี้ / เลือกเดือน
- ตัวเลขสรุป 6 ช่อง (มือถือแถวละคู่): ยอดสุทธิ · บิล | กำไรขั้นต้น · กำไรหลังหัก | ของเสีย/หมดอายุ/เบิกใช้ · ยกเลิก/คืน/ส่วนลด
- กราฟ (Chart.js รูปแบบเดียวกับ FIFO Dashboard: เส้น+พื้นจาง, เส้นค่าเฉลี่ย, ป้ายล่าสุด/สูงสุด/ต่ำสุด):
  - ยอดขายรายวัน (หรือรายเดือน) — แตะจุดเพื่อดูวัน/เดือนนั้น
  - แยกตามหมวด: **เทียบกัน** (อันดับทั้งช่วง + เส้นแนวโน้ม เน้นทีละหมวด) หรือ **แยกการ์ด** (กราฟเล็กหมวดละใบ)
  - ยอดขายรายชั่วโมง (โหมดรายวัน) — รวมทุกวันในช่วงที่เลือก
- **ตารางย้อนหลัง** วันละแถว / เดือนละแถว: ยอด เทียบก่อนหน้า ▲▼ กำไร ของเสีย กำไรหลังหัก — แตะแถวเพื่อเจาะดู
- รายการผิดปกติ รวม **ราคาขายต่ำกว่าทุน** และ **กำไรต่ำกว่า 10%**
- ตัวกรองเพิ่มเติม (ซ่อนไว้): หมวด · สินค้า · พนักงาน · กะ · ช่องทางชำระ · เครื่อง · ประเภทบิล
- แท็บอื่น: สินค้า (กำไรต่อสินค้า) · หมวด · พนักงาน · กะ · ไม่เคลื่อนไหว · มูลค่าสต็อก
- Chart.js 4.5.1 เก็บไว้ใน repo (web/vendor) ใช้ได้แม้เน็ตไม่ดี
